## Purpose

Описывает, откуда система берёт шаблоны документов: как файлы разложены в репозитории, как из них появляются записи о шаблонах на стенде и что с шаблонами можно делать в интерфейсе и через API.

## ADDED Requirements

### Requirement: Раскладка шаблонов по папкам стадий

Файлы шаблонов SHALL лежать в каталоге шаблонов в папках по стадиям: `basic_info`, `pre_court`, `judicial_procedure_initiation`, `judicial_procedure`, `judicial_report`. Имя папки задаёт категорию шаблона, имя файла без расширения — название, которое видит юрист. Регистрируются файлы `.docx` и `.xlsx`; файлы других расширений и файлы, лежащие вне папок стадий, система пропускает.

Пара «категория и название» SHALL быть уникальной: два файла с одинаковым именем в одной папке невозможны по природе файловой системы, а одинаковые имена в разных папках дают разные шаблоны.

#### Scenario: Новый документ добавлен файлом

- **WHEN** разработчик кладёт в репозиторий файл `judicial_report/2. Реестр требований кредиторов.docx` и выкатывает изменения
- **THEN** на стенде появляется шаблон с названием «2. Реестр требований кредиторов» в категории «Судебка отчет», и юрист видит его на вкладке «Судебка → Отчёт» карточки дела

#### Scenario: Файл вне папки стадии

- **WHEN** в корне каталога шаблонов лежит файл, загруженный до перехода на раскладку по папкам
- **THEN** он не регистрируется и не меняет существующие записи

### Requirement: Регистрация шаблонов на деплое

Команда синхронизации шаблонов SHALL раскладывать файлы из образа в каталог шаблонов и после этого создавать и обновлять записи о шаблонах по данным файлов. Она выполняется при каждом выкате, после миграций базы.

Правила регистрации:

- запись ищется по категории и названию: найденная обновляет путь на файл из репозитория, ненайденная создаётся;
- запись, путь которой ведёт на несуществующий файл, удаляется;
- повторный запуск команды на тех же файлах ничего не меняет;
- команда сообщает, сколько записей создано, обновлено и удалено.

#### Scenario: Шаблон, загруженный раньше через интерфейс

- **WHEN** на стенде есть запись «1. Публикация ЕФРСБ» категории «Судебка введение процедуры», созданная загрузкой, а в репозитории появился файл `judicial_procedure_initiation/1. Публикация ЕФРСБ.docx`
- **THEN** после выката запись остаётся той же, а её путь указывает на файл из репозитория; новая запись не создаётся

#### Scenario: Шаблон удалён из репозитория

- **WHEN** файл шаблона удалён из репозитория и выкат прошёл
- **THEN** запись о нём удаляется, и шаблон пропадает из списка и из вкладок карточки дела

#### Scenario: Повторный запуск

- **WHEN** команда синхронизации выполняется второй раз подряд без изменений в файлах
- **THEN** она сообщает «создано 0, обновлено 0, удалено 0», а записи и файлы остаются прежними

### Requirement: Шаблоны только читаются через интерфейс и API

Система MUST NOT принимать шаблоны документов через интерфейс и API. `POST /api/v1/document-templates` и `PUT /api/v1/document-templates/{id}` SHALL отвечать 405, как это уже сделано с удалением шаблона.

На странице «Шаблоны документов» SHALL остаться список с поиском и фильтром по категории, просмотр шаблона и скачивание. Блока «Загрузить новый шаблон» на странице быть не должно. В карточке дела остаются просмотр, скачивание и генерация документа по делу.

#### Scenario: Попытка загрузить шаблон запросом

- **WHEN** авторизованный пользователь отправляет `POST /api/v1/document-templates` с файлом
- **THEN** ответ — 405, файл не сохраняется и записи не появляются

#### Scenario: Страница шаблонов

- **WHEN** юрист открывает «Шаблоны документов»
- **THEN** он видит список шаблонов, поиск, фильтр по категории, кнопки просмотра и скачивания и не видит блока загрузки

#### Scenario: Генерация по делу не меняется

- **WHEN** юрист нажимает «Скачать» у шаблона на вкладке стадии в карточке дела
- **THEN** документ генерируется и скачивается, как раньше
