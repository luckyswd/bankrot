## Purpose

Описывает данные дела, которые юрист ведёт на судебных стадиях — введение
процедуры, ход реализации имущества и отчёт: что вводится вручную, что система
рассчитывает сама, на какой вкладке карточки дела это отображается и как
передаётся через API дела.

## ADDED Requirements

### Requirement: Публикации о признании гражданина банкротом

На вкладке «Судебка → Введение процедуры» SHALL появиться блок «Публикации» с
двумя подблоками. Поля входят в группу сериализации
`judicial_procedure_initiation` и передаются в `GET/PUT /api/v1/contracts/{id}`
в разделе `judicial_procedure_initiation`.

| Подблок | Поле в интерфейсе | Поле API | Формат |
|---|---|---|---|
| ЕФРСБ | Номер сообщения | `procedureInitiationEfrsbMessageNumber` | строка до 255 символов |
| ЕФРСБ | Дата сообщения | `procedureInitiationEfrsbMessageDate` | дата |
| Коммерсантъ | Номер издания | `procedureInitiationKommersantIssueNumber` | строка до 255 символов, например «139 (7101)» |
| Коммерсантъ | Номер объявления | `procedureInitiationKommersantAdNumber` | строка до 255 символов |
| Коммерсантъ | Дата публикации | `procedureInitiationKommersantPublicationDate` | дата |
| Коммерсантъ | Стоимость публикации, руб. | `procedureInitiationKommersantPublicationCost` | сумма ≥ 0, два знака после запятой |

Все поля необязательны. Пустое значение MUST сохраняться как отсутствие значения
и не возвращаться API. Здесь и далее даты в `PUT` передаются строкой `ГГГГ-ММ-ДД`,
а в ответе возвращаются в формате ISO 8601 (`2025-02-07T00:00:00+03:00`), как
остальные даты дела; суммы — строкой с точкой (`"7866.05"`). Возможность доступна любому авторизованному пользователю
(`ROLE_USER` и выше), как и остальные поля дела.

#### Scenario: Ввод публикации в Коммерсанте

- **WHEN** юрист на вкладке «Введение процедуры» вводит номер издания «139 (7101)»,
  номер объявления «78230149776», дату 07.02.2025, стоимость 7866,05 и сохраняет дело
- **THEN** `GET /api/v1/contracts/{id}` в разделе `judicial_procedure_initiation`
  возвращает `"procedureInitiationKommersantIssueNumber": "139 (7101)"`,
  `"procedureInitiationKommersantAdNumber": "78230149776"`,
  `procedureInitiationKommersantPublicationDate` с датой 2025-02-07 и
  `"procedureInitiationKommersantPublicationCost": "7866.05"`

#### Scenario: Отрицательная стоимость

- **WHEN** юрист вводит стоимость публикации меньше нуля
- **THEN** под полем отображается «Сумма не может быть отрицательной»

### Requirement: Уведомление кредиторов почтой

На вкладке «Судебка → Введение процедуры» SHALL появиться блок «Уведомление
кредиторов почтой» с полем «Дата направления уведомлений»
(`procedureInitiationCreditorsNotificationDate`, дата, группа
`judicial_procedure_initiation`).

#### Scenario: Сохранение даты уведомления

- **WHEN** юрист выбирает дату 10.02.2025 и сохраняет дело
- **THEN** API возвращает `procedureInitiationCreditorsNotificationDate` с датой 2025-02-10,
  а после перезагрузки страницы дата отображается в блоке

### Requirement: Дата закрытия реестра рассчитывается

На вкладке «Судебка → Введение процедуры» SHALL появиться блок «Дата закрытия
реестра». Дата MUST рассчитываться как дата публикации в «Коммерсантъ» плюс два
календарных месяца. Если в последнем месяце нет такого числа, реестр закрывается
в последний день этого месяца (п. 3 ст. 192 ГК РФ).

Поле доступно только для чтения, пересчитывается в интерфейсе сразу при изменении
даты публикации и возвращается API как `registryClosingDate` в разделе
`judicial_procedure_initiation`. Значение `registryClosingDate`, переданное в
`PUT`, MUST игнорироваться. Пока дата публикации в «Коммерсантъ» не заполнена,
блок показывает «Заполните дату публикации в «Коммерсантъ»», а API поле не
возвращает.

#### Scenario: Пример заказчика

- **WHEN** дата публикации в «Коммерсантъ» — 08.04.2026
- **THEN** дата закрытия реестра — 08.06.2026

#### Scenario: В конечном месяце нет такого числа

- **WHEN** дата публикации в «Коммерсантъ» — 31.12.2025
- **THEN** дата закрытия реестра — 28.02.2026

#### Scenario: Пересчёт до сохранения

- **WHEN** юрист меняет дату публикации с 07.02.2025 на 17.05.2025, не сохраняя дело
- **THEN** в блоке «Дата закрытия реестра» сразу отображается 17.07.2025

#### Scenario: Попытка записать дату закрытия напрямую

- **WHEN** в `PUT /api/v1/contracts/{id}` передано `"registryClosingDate": "2030-01-01"`
  при дате публикации 07.02.2025
- **THEN** API возвращает `registryClosingDate` с датой 2025-04-07

### Requirement: Продление процедуры реализации имущества

На вкладке «Судебка → Процедура» SHALL появиться блок «Продление процедуры» с
выбором одного из вариантов (группа `judicial_procedure`, поле
`procedureExtensionStatus`):

| Вариант в интерфейсе | Значение API |
|---|---|
| Процедура продлевалась | `extended` |
| Процедура реализации имущества не продлевалась | `not_extended` |
| Судебные акты не выносились | `no_acts` |

При варианте «Процедура продлевалась» блок SHALL показывать список дат судебных
актов о продлении с кнопками «Добавить дату» и удаления строки
(`procedureExtensionDates` — массив строк `ГГГГ-ММ-ДД` в порядке ввода, в ответе возвращается в том же виде). При других
вариантах список скрыт, а после сохранения API не возвращает
`procedureExtensionDates`.

#### Scenario: Две даты продления

- **WHEN** юрист выбирает «Процедура продлевалась», добавляет даты 12.03.2026 и
  10.09.2026 и сохраняет дело
- **THEN** API возвращает `"procedureExtensionStatus": "extended"` и
  `"procedureExtensionDates": ["2026-03-12", "2026-09-10"]`

#### Scenario: Смена варианта удаляет даты

- **WHEN** у дела сохранены даты продления, юрист выбирает «Процедура реализации
  имущества не продлевалась» и сохраняет дело
- **THEN** API возвращает `"procedureExtensionStatus": "not_extended"` и не
  возвращает `procedureExtensionDates`

### Requirement: Дата описи имущества

На вкладке «Судебка → Процедура» SHALL появиться блок «Опись имущества» с полем
«Дата описи» (`propertyInventoryDate`, дата, группа
`judicial_procedure`). Это же поле позже использует документ «Опись имущества
гражданина».

#### Scenario: Сохранение даты описи

- **WHEN** юрист выбирает 02.07.2025 и сохраняет дело
- **THEN** API возвращает `propertyInventoryDate` с датой 2025-07-02

### Requirement: Ответ ЗАГС

На вкладке «Судебка → Процедура» SHALL появиться блок «Ответы из госорганов» с
подблоком «ЗАГС» (группа `judicial_procedure`):

| Поле в интерфейсе | Поле API | Формат |
|---|---|---|
| Отдел ЗАГС | `zagsDepartment` | строка до 500 символов |
| Справка за период с | `zagsCertificatePeriodFrom` | дата |
| Справка за период по | `zagsCertificatePeriodTo` | дата |

Если отдел ЗАГС в деле не сохранён, поле SHALL показывать текст по умолчанию
«отдел ЗАГС Комитета по делам ЗАГС Правительства Санкт-Петербурга», который юрист
может переписать. Отдельного справочника ЗАГС нет. Если юрист сотрёт текст
полностью и сохранит дело, поле снова показывает текст по умолчанию.

Если дата «с» позже даты «по», интерфейс SHALL показывать «Дата начала периода
позже даты окончания» под полем «по».

#### Scenario: Текст по умолчанию

- **WHEN** юрист впервые открывает блок «Ответы из госорганов» в деле
- **THEN** в поле «Отдел ЗАГС» стоит «отдел ЗАГС Комитета по делам ЗАГС
  Правительства Санкт-Петербурга»

#### Scenario: Свой отдел ЗАГС

- **WHEN** юрист заменяет текст на «Отдел ЗАГС администрации Всеволожского
  муниципального района Ленинградской области» и сохраняет дело
- **THEN** API возвращает этот текст в `zagsDepartment`, а после перезагрузки
  поле показывает его, а не текст по умолчанию

#### Scenario: Период перепутан местами

- **WHEN** юрист вводит период с 10.07.2025 по 11.02.2009
- **THEN** под полем «по» отображается «Дата начала периода позже даты окончания»

### Requirement: Результаты рассмотрения требований кредиторов

На вкладке «Судебка → Процедура» SHALL появиться блок «Результаты рассмотрения
требований» (группа `judicial_procedure`):

| Поле в интерфейсе | Поле API | Формат |
|---|---|---|
| Включено в реестр | `claimsIncludedCount` | целое ≥ 0 |
| Отказано во включении в реестр | `claimsRejectedCount` | целое ≥ 0 |
| Всего рассмотрено в арбитражном суде | `claimsConsideredCount` | только чтение |

«Всего рассмотрено» MUST равняться сумме двух введённых чисел, пересчитываться в
интерфейсе при каждом изменении и возвращаться API; переданное в `PUT` значение
MUST игнорироваться. Если оба числа не заполнены, «Всего рассмотрено» пусто и API
его не возвращает. Числа вводятся вручную и не зависят от строк таблицы
требований кредиторов.

#### Scenario: Подсчёт итога

- **WHEN** юрист вводит «Включено в реестр» 2 и «Отказано во включении» 0
- **THEN** «Всего рассмотрено» показывает 2, а после сохранения API возвращает
  `"claimsIncludedCount": 2`, `"claimsRejectedCount": 0`,
  `"claimsConsideredCount": 2`

### Requirement: Расходы на проведение процедуры

На вкладке «Судебка → Процедура» SHALL появиться блок «Расходы на проведение
процедуры» — таблица из четырёх фиксированных позиций (группа
`judicial_procedure`). Суммы — ≥ 0 с двумя знаками после запятой, в API
передаются строкой с точкой: `"560.55"`.

| Позиция | Размер обязательства | Погашено | Непогашенный остаток |
|---|---|---|---|
| Расходы на опубликование сообщений на ЕФРСБ | `efrsbExpensesAmount` | `efrsbExpensesPaid` | `efrsbExpensesUnpaid` |
| Почтовые расходы | `postalExpensesAmount` | `postalExpensesPaid` | `postalExpensesUnpaid` |
| Расходы на опубликование сообщений в газетах | `newspaperExpensesAmount` | `newspaperExpensesPaid` | `newspaperExpensesUnpaid` |
| Будущие расходы на опубликование сообщений на ЕФРСБ | `futureEfrsbExpensesAmount` | `futureEfrsbExpensesPaid` | `futureEfrsbExpensesUnpaid` |

- «Размер обязательства» и «Погашено» вводятся вручную, кроме размера расходов на
  газеты: он MUST равняться стоимости публикации в «Коммерсантъ» с вкладки
  «Введение процедуры» и доступен только для чтения с подписью «Из публикации в
  «Коммерсантъ»».
- «Непогашенный остаток» MUST равняться размеру обязательства минус погашенную
  сумму, где пустое значение считается нулём, и пересчитываться в интерфейсе при
  каждом изменении.
- Если погашено больше размера обязательства, под полем «Погашено» SHALL
  отображаться «Погашено больше размера обязательства». Сохранение при этом не
  блокируется, остаток показывается отрицательным.
- Поля только для чтения (`newspaperExpensesAmount`, `*Unpaid`) возвращаются API
  при наличии хотя бы одного исходного значения; переданные в `PUT` значения MUST
  игнорироваться.

#### Scenario: Остаток считается сам

- **WHEN** юрист вводит по ЕФРСБ размер 560,55 и погашено 29,67
- **THEN** «Непогашенный остаток» сразу показывает 530,88, а после сохранения API
  возвращает `"efrsbExpensesUnpaid": "530.88"`

#### Scenario: Расходы на газеты из публикации

- **WHEN** на вкладке «Введение процедуры» стоимость публикации в «Коммерсантъ»
  7866,05, а в строке газет погашено ничего не введено
- **THEN** в строке «Расходы на опубликование сообщений в газетах» размер
  обязательства 7866,05 и непогашенный остаток 7866,05

#### Scenario: Погашено больше, чем должно

- **WHEN** у почтовых расходов размер 1490,00, а юрист вводит погашено 1500,00
- **THEN** под полем отображается «Погашено больше размера обязательства», остаток
  показывает −10,00, сохранить дело можно

### Requirement: Дата публикации о признаках фиктивного и преднамеренного банкротства

На вкладке «Судебка → Процедура» SHALL появиться блок «Фиктивные и преднамеренные
признаки банкротства» с полем «Дата публикации в ЕФРСБ»
(`bankruptcySignsEfrsbPublicationDate`, дата, группа
`judicial_procedure`). Эта дата используется в документах как дата проведения
финансового анализа.

#### Scenario: Сохранение даты публикации

- **WHEN** юрист выбирает 14.05.2026 и сохраняет дело
- **THEN** API возвращает `bankruptcySignsEfrsbPublicationDate` с датой 2026-05-14

### Requirement: Документы стадии «Отчёт» видны на вкладке

Вкладка «Судебка → Отчёт» SHALL показывать список шаблонов категории «Судебка
отчет» (`judicial_report`) с индикатором заполненности полей, открытием
предпросмотра и скачиванием — так же, как вкладки «Введение процедуры» и
«Процедура» показывают свои шаблоны. Надпись «Раздел в разработке» MUST
исчезнуть.

#### Scenario: Загруженный шаблон отчёта

- **WHEN** в разделе «Документы» загружен шаблон «1. Отчёт финансового
  управляющего» с категорией «Судебка отчет», и юрист открывает вкладку
  «Судебка → Отчёт» в деле
- **THEN** шаблон отображается в списке документов, по нажатию открывается
  предпросмотр документа с данными дела

#### Scenario: Переход к незаполненному полю

- **WHEN** в деле не заполнена дата публикации в «Коммерсантъ», и юрист нажимает
  на это поле в списке незаполненных у шаблона отчёта
- **THEN** открывается вкладка «Судебка → Введение процедуры» с блоком «Публикации»
