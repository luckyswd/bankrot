## Context

Мотивация — в `proposal.md`, требования — в `specs/documents/property-inventory/spec.md`.

Исходник заказчика — `.doc` (Word 97), шаблонизатор работает только с `.docx` и `.xlsx`. Оба предыдущих документа пакета («Отчёт финансового управляющего», «Реестр требований кредиторов») лежат в репозитории как `.docx`, сконвертированные тем же LibreOffice (`docProps/app.xml` → `LibreOffice/26.8.0.3`). Цветная разметка заказчика в исходнике описи — 12 прогонов: 11 зелёных (данные должника) и 1 красный (дата описи).

Кода изменение не требует: все значения отдают существующие геттеры `Contracts`, а список полей для счётчика заполненности `DocumentTemplateProcessor::extractFields()` выводит из плейсхолдеров шаблона рефлексией. Шаблон попадает в базу командой синхронизации, которая регистрирует файлы из папок стадий.

## Goals / Non-Goals

**Goals:**

- Шаблон описи, по которому генерируется документ, пригодный для суда без правки шапки и таблицы сведений о гражданине.
- Проверка шаблона автотестом, как у двух предыдущих документов пакета.

**Non-Goals:**

- Новые поля, миграции, изменения API и фронтенда.
- Блок «Имущество» и подстановка реквизитов финансового управляющего — см. «Вне рамок» в `proposal.md`.

## Decisions

**Конвертация `.doc` → `.docx` через LibreOffice в headless-режиме.** Так сделаны оба предыдущих шаблона, вёрстка формы сохраняется, результат воспроизводим одной командой. Альтернатива — пересобирать форму вручную в редакторе: дороже и даёт расхождения с образцом заказчика.

**Плейсхолдеры вставляются правкой `word/document.xml` скриптом.** Нужно заменить текст ровно тех прогонов, которые заказчик пометил цветом, и снять с них `<w:color>`. Скрипт по XML делает это точечно и повторяемо; ручная правка в редакторе не воспроизводится и рискует задеть соседние прогоны. Опорой служит цвет: `00B050` — данные должника, `FF0000` — дата описи.

**Новых геттеров и методов-формулировок не заводим.** Все одиннадцать значений уже отдаются существующими методами `Contracts`, в том числе `getPreviousFullName()` с прочерком и `getPropertyInventoryDateText()` в формате «дд» месяц гггг г. Заводить обёртки только ради описи — лишний код.

**Тест шаблона — по образцу `CreditorsRegisterTemplateTest`:** генерация из шаблона репозитория, проверка отсутствия маркеров, валидности XML, конкретных подставленных значений и отсутствия окрашенных прогонов. Данные должника берёт фабрика тестовых дел; ей нужны паспорт и дата описи, которых сейчас нет в `RegisterContractFactory`, — опись собирает своё дело в тесте, чтобы не менять ожидания реестра.

## Risks / Trade-offs

- **Конвертация LibreOffice меняет вёрстку формы** (шрифты, ширина колонок) → сверяем сгенерированный документ с исходником заказчика в сквозной проверке, абзац за абзацем, как для документов 1 и 2.
- **Плейсхолдер разрывается на несколько прогонов** и шаблонизатор его не видит → текст плейсхолдера пишем в один прогон, а тест проверяет, что в готовом файле не осталось `{{`.
- **Таблицы имущества остаются прочерками** → юрист дописывает их руками; это зафиксировано в «Вне рамок», а не скрыто в реализации.
